# Contributing

## Workflow

1. Create a focused branch from `develop`.
2. Keep each change small and logically scoped.
3. Run the repository quality checks before opening a pull request.
4. Open a pull request into `develop` with a clear description and validation evidence.
5. Merge to `main` only after CI is green.

## Quality bar

Changes should preserve:

- semantic HTML and accessibility
- responsive behavior across mobile, tablet and desktop
- bilingual SEO and reciprocal hreflang
- valid structured data
- working internal links and assets
- strong performance and Core Web Vitals
- factual professional claims only

Never commit credentials, API keys, tokens, private keys or other secrets.
