روش مهندسی عیب‌یابی شبکه: Evidence → Hypothesis → Test

عیب‌یابی حرفه‌ای با تغییر تنظیمات شروع نمی‌شود؛ با تعریف دقیق مسئله و جمع‌آوری Evidence شروع می‌شود.

Pipeline: Symptom → Scope → Baseline → Evidence → Hypothesis → Controlled Test → Root Cause → Fix → Validation → Documentation

۱. Scope را مشخص کنید

اول مشخص کنید مشکل برای چه کاربران، سرویس‌ها، VLANها، مقصدها و بازه زمانی رخ می‌دهد. یک مشکل سراسری با یک مشکل نقطه‌ای روش بررسی متفاوتی دارد.

۲. Baseline بگیرید

Latency، packet loss، DNS response، interface errors، CPU، memory و وضعیت سرویس را با زمان ثبت کنید. بدون baseline، مقایسه نتیجه دشوار است.

۳. فرضیه بسازید

هر فرضیه باید قابل آزمایش باشد؛ مثلاً DNS latency، route asymmetry، congestion یا service-side latency. یک فرضیه را با یک تست مشخص بررسی کنید.

۴. Change کنترل‌شده

اگر تغییر لازم شد، فقط یک متغیر را تغییر دهید، نتیجه را ثبت کنید و مسیر Rollback داشته باشید.

۵. Root Cause را از Symptom جدا کنید

رفع موقت symptom لزوماً Root Cause نیست. بعد از اصلاح، همان Evidence را دوباره اندازه‌گیری کنید و مطمئن شوید مشکل واقعاً برطرف شده است.

۶. مستندسازی

Timeline، Evidence، Hypothesis، Change، Result و Lesson Learned را ثبت کنید تا دفعه بعد Troubleshooting سریع‌تر و قابل تکرار باشد.
