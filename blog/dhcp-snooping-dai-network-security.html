DHCP Snooping و Dynamic ARP Inspection؛ دو لایه مهم امنیت شبکه

بخش مهمی از امنیت شبکه قبل از فایروال اتفاق می‌افتد: روی سوئیچ Access. اگر یک سیستم غیرمجاز بتواند DHCP Server جعلی راه بیندازد یا ARP جعلی منتشر کند، بخشی از کنترل ترافیک از دست می‌رود. DHCP Snooping و DAI برای همین سناریوها طراحی شده‌اند.

انتشار: ۷ سپتامبر ۲۰۲۶ · موضوع: Network Security

مسئله دقیقاً چیست؟

در یک شبکه لایه ۲، کلاینت برای گرفتن IP از DHCP پیام Broadcast ارسال می‌کند. اگر یک دستگاه غیرمجاز به شبکه وصل شود و به درخواست DHCP پاسخ دهد، ممکن است کلاینت‌ها Gateway یا DNS اشتباه دریافت کنند. این سناریو با عنوان Rogue DHCP شناخته می‌شود.

در سمت دیگر، ARP ذاتاً مکانیزم احراز هویت ندارد. یک مهاجم می‌تواند با ارسال پاسخ‌های جعلی، نگاشت IP به MAC را دستکاری کند و زمینه حملاتی مانند ARP Spoofing یا Man-in-the-Middle را فراهم کند.

اصل طراحی: به جای اینکه فقط روی Endpoint یا Firewall حساب کنیم، Access Switch را هم به یک نقطه کنترل تبدیل می‌کنیم؛ DHCP Snooping منبع معتبر DHCP را مشخص می‌کند و DAI از اطلاعات قابل اعتماد برای اعتبارسنجی ARP استفاده می‌کند.

DHCP Snooping چه کاری انجام می‌دهد؟

سوئیچ پورت‌ها را از نظر DHCP به دو گروه منطقی تقسیم می‌کند: Trusted و Untrusted. پورت متصل به DHCP Server یا Uplink مورد اعتماد است؛ پورت‌های کاربر عادی Untrusted می‌مانند. پاسخ‌های DHCP Server از پورت Untrusted نباید پذیرفته شوند.

یکی از خروجی‌های مهم DHCP Snooping، جدول binding است که معمولاً شامل IP، MAC، VLAN و Interface می‌شود. این جدول بعداً می‌تواند برای قابلیت‌هایی مانند Dynamic ARP Inspection استفاده شود.

یک الگوی پیاده‌سازی نمونه

Syntax بسته به Vendor و مدل سوئیچ متفاوت است. نمونه زیر یک الگوی رایج Cisco IOS است و نباید بدون تطبیق با مستندات مدل دقیق روی تجهیزات Production اجرا شود:

ip dhcp snooping
ip dhcp snooping vlan 10,20
!
interface GigabitEthernet1/0/48
 ip dhcp snooping trust
!
interface range GigabitEthernet1/0/1-47
 no ip dhcp snooping trust
 ip dhcp snooping limit rate 15

نکته مهم این است که Trust را روی پورت کاربر فعال نکنید. اگر Access Port اشتباهاً Trusted شود، بخشی از کنترل ضد Rogue DHCP از بین می‌رود.

Dynamic ARP Inspection چگونه وارد ماجرا می‌شود؟

DAI درخواست‌ها و پاسخ‌های ARP را بررسی می‌کند و در پیاده‌سازی‌های متداول، آن‌ها را با DHCP Snooping Binding Table مقایسه می‌کند. اگر IP/MAC/Interface با اطلاعات معتبر همخوانی نداشته باشد، فریم ARP می‌تواند Drop شود.

ip arp inspection vlan 10,20
!
interface GigabitEthernet1/0/48
 ip arp inspection trust

مانند DHCP Snooping، پورت‌های Uplink یا مسیرهای واقعاً مورد اعتماد باید با دقت مشخص شوند. Trust کردن گسترده پورت‌ها عملاً ارزش کنترل را کاهش می‌دهد.

اگر کلاینت Static IP داشته باشد چه؟

اینجا یکی از نقاطی است که اجرای کورکورانه DAI باعث اختلال می‌شود. دستگاه‌هایی با IP ثابت الزاماً در DHCP Snooping Binding Table وجود ندارند. برای چنین تجهیزات، باید از روش مناسب همان Vendor، مانند ARP ACL یا Static Binding، استفاده شود.

قبل از فعال‌سازی در Production: Printer، Access Point، دوربین، تلفن IP، سرورهای Static و تجهیزات مدیریتی را فهرست کنید و رفتارشان را در VLAN مربوطه بررسی کنید.

چه چیزهایی را باید مانیتور کنیم؟

  • تعداد و علت Drop شدن DHCP و ARP.
  • پورت‌هایی که به‌صورت غیرمنتظره DHCP Server Response تولید می‌کنند.
  • تغییرات Binding بین IP و MAC.
  • خطاهای مرتبط با IPهای Static و تجهیزات Legacy.
  • لاگ‌های سوئیچ و ارسال آن‌ها به Syslog یا SIEM در محیط‌های سازمانی.

اشتباهات رایج

  1. Trusted کردن همه پورت‌ها: کنترل امنیتی عملاً بی‌اثر می‌شود.
  2. فعال‌سازی مستقیم روی کل شبکه: بدون Inventory و تست، احتمال قطع تجهیزات Static وجود دارد.
  3. نادیده گرفتن Uplinkها: ممکن است DHCP معتبر یا ترافیک مورد نیاز Drop شود.
  4. نداشتن Logging: تشخیص اینکه چه چیزی Drop شده سخت می‌شود.
  5. وابستگی به یک قابلیت: DHCP Snooping و DAI جایگزین Segmentation، NAC، Port Security، 802.1X و مانیتورینگ نیستند.

یک طراحی منطقی برای شبکه سازمانی

در یک معماری لایه‌ای می‌توان Access Switch را با DHCP Snooping و DAI سخت‌سازی کرد، VLANها را بر اساس نقش جدا کرد، روی پورت‌ها محدودیت و کنترل مناسب قرار داد و سپس در لایه‌های بالاتر از Firewall، NAC، ACL و مانیتورینگ استفاده کرد. هدف این نیست که یک قابلیت همه مشکلات را حل کند؛ هدف کاهش سطح حمله در چند نقطه مستقل است.

چک‌لیست قبل از اجرا

  • DHCP Serverهای معتبر را مشخص کرده‌اید؟
  • Uplink و Trunkهای معتبر را مشخص کرده‌اید؟
  • VLANهای مشمول کنترل را دقیق انتخاب کرده‌اید؟
  • تجهیزات Static IP را شناسایی کرده‌اید؟
  • Rate Limit مناسب برای DHCP در نظر گرفته‌اید؟
  • Logging و مانیتورینگ فعال است؟
  • Rollback plan دارید؟
  • ابتدا روی یک VLAN آزمایشی تست کرده‌اید؟

جمع‌بندی

امنیت شبکه فقط فایروال و Antivirus نیست. Access Layer می‌تواند اولین نقطه‌ای باشد که جلوی یک DHCP Server جعلی یا ARP Spoofing را می‌گیرد. DHCP Snooping و Dynamic ARP Inspection، وقتی درست طراحی و مانیتور شوند، دو کنترل مؤثر برای سخت‌سازی لایه ۲ هستند؛ اما باید در کنار Segmentation، کنترل دسترسی، لاگینگ و سایر لایه‌های امنیتی استفاده شوند.

برای مطالعه مرتبط، راهنمای Segmentation با VLAN و مقاله سخت‌سازی شبکه را هم ببینید.
