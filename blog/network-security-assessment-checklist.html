چک‌لیست ارزیابی امنیت شبکه؛ از Asset Discovery تا Incident Response

ارزیابی امنیت شبکه زمانی ارزشمند است که از یک فهرست ابزار به یک فرآیند تصمیم‌گیری تبدیل شود. این چک‌لیست کمک می‌کند دارایی‌ها، مسیرهای دسترسی، کنترل‌های امنیتی، شواهد و شکاف‌های واقعی را مرحله‌به‌مرحله ثبت و اولویت‌بندی کنید.

نویسنده: محمدحسین عسگری ثمرینسطح: متوسط تا پیشرفتهآخرین ویرایش: ۲۴ شهریور ۱۴۰۵

۱. Asset Discovery و مالکیت

بدون فهرست دارایی، ارزیابی امنیت ناقص است. سرورها، سوئیچ‌ها، فایروال‌ها، Access Pointها، دوربین‌ها، پرینترها، تجهیزات IoT، سرویس‌های ابری و نقاط دسترسی راه دور را ثبت کنید. برای هر دارایی مالک، محل، IP/VLAN، نقش، سطح حساسیت و روش مدیریت را مشخص کنید.

  • دارایی ناشناخته را به‌عنوان ریسک در نظر بگیر.
  • IPهای رزرو، DNS و نام سیستم‌ها را با واقعیت شبکه تطبیق بده.
  • دارایی‌های End-of-Life را جداگانه علامت‌گذاری کن.

۲. مسیرهای ارتباطی و Attack Surface

فقط پورت باز را نبین؛ مسیر واقعی ارتباط را مدل کن. اینترنت، VPN، Remote Management، ارتباط Server-to-Server و دسترسی کاربران به سرویس‌های حساس را مشخص کن. هر مسیر باید دلیل کسب‌وکاری و کنترل مناسب داشته باشد.

۳. Segmentation و Access Control

بررسی کن آیا Client، Server، Management، Voice، CCTV و Guest در محدوده‌های منطقی قرار گرفته‌اند. سپس Ruleهای بین VLANها و Zoneها را با نیاز واقعی مقایسه کن. دسترسی مدیریتی باید محدودتر از دسترسی کاربری باشد و مسیرهای حساس ترجیحاً از یک Management Plane مشخص عبور کنند.

۴. لایه Access و حملات داخلی

DHCP Snooping، Dynamic ARP Inspection، Port Security، خاموش بودن پورت‌های بلااستفاده و کنترل Trusted Portها را بررسی کن. مهم است که این کنترل‌ها واقعاً با مدل سوئیچ و توپولوژی سازگار باشند؛ یک تنظیم اشتباه می‌تواند خودش باعث قطعی شود.

۵. Firewall و Rule Review

برای هر Rule حداقل Source، Destination، Service، Purpose، Owner و وضعیت Logging را بررسی کن. Ruleهای Any/Any، Exceptionهای قدیمی، Objectهای بدون استفاده و Policyهای بدون مالک باید وارد فرآیند بازبینی شوند. تغییر Rule بدون بررسی Log و Hit Count می‌تواند هم ریسک و هم پیچیدگی را افزایش دهد.

۶. Identity و Privileged Access

حساب روزمره و حساب مدیریتی را جدا کن. گروه‌های privileged، Service Accountها، GPOهای حساس، MFA، محدودیت Source IP برای Management و رویدادهای Authentication Failure را بررسی کن. اصل Least Privilege باید قابل اثبات و دوره‌ای باشد.

۷. Logging و Detection

مشخص کن کدام رویدادها باید جمع‌آوری، نگهداری و بررسی شوند: Loginهای ناموفق، تغییر Rule فایروال، تغییر عضویت گروه‌های حساس، تغییر DNS، خطاهای سرویس، افزایش ناگهانی ترافیک و وضعیت Backup. داشتن Log بدون تعریف Signalهای مهم، Monitoring واقعی نیست.

۸. Vulnerability و Patch Management

نسخه سیستم‌عامل، Firmware تجهیزات شبکه، سرویس‌های اینترنتی و نرم‌افزارهای مدیریتی را با وضعیت پشتیبانی مقایسه کن. اولویت Patch را بر اساس Exposure، Exploitability، حساسیت دارایی و وجود کنترل جبرانی تعیین کن؛ نه صرفاً بر اساس تعداد CVE.

۹. Backup و Recovery

برای تنظیمات Firewall و Switch، سیستم‌عامل‌ها، دیتابیس‌ها و فایل‌های حیاتی Backup داشته باش. سپس Restore Test انجام بده. Backupی که هرگز بازیابی نشده، فقط یک فرض است. RPO، RTO، محل نگهداری و دسترسی به Backup را مستند کن.

۱۰. Incident Response

برای رخدادهای رایج Runbook داشته باش: تشخیص، محدودسازی، حفظ شواهد، حذف علت، بازیابی، اعتبارسنجی و Lessons Learned. قبل از Reboot یا پاک‌سازی سیستم مشکوک، اثر آن اقدام روی شواهد را بررسی کن.

۱۱. تبدیل یافته‌ها به Risk Register

هر یافته باید مالک، شواهد، اثر، احتمال، اولویت، اقدام اصلاحی و مهلت داشته باشد. یک یافته بدون Owner معمولاً به یک کار عقب‌افتاده تبدیل می‌شود.

Finding → Evidence → Impact → Likelihood → Priority → Owner → Fix → Validation

۱۲. معیار پایان ارزیابی

ارزیابی وقتی تمام می‌شود که کنترل‌های مهم فقط «فعال» نباشند، بلکه قابل اعتبارسنجی باشند. برای هر اصلاح، یک Test تعریف کن: آیا Guest به Server VLAN دسترسی دارد؟ آیا DHCP Rogue قابل شناسایی است؟ آیا Management فقط از Sourceهای مجاز پذیرفته می‌شود؟ آیا Restore واقعاً انجام می‌شود؟

اگر می‌خواهی همین مدل روی یک محیط واقعی اجرا شود

می‌توان این فرآیند را به‌صورت Assessment، Hardening، مستندسازی و برنامه اصلاحی برای شبکه و زیرساخت اجرا کرد.
