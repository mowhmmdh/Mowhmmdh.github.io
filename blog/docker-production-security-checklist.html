چک‌لیست امنیت Docker در Production

Docker اجرای سریع سرویس‌ها را ساده می‌کند، اما Container به‌خودی‌خود مرز امنیتی کامل نیست. در محیط Production باید Image، Secret، Network، Volume، Runtime و Host همزمان بررسی شوند.

Image

از Imageهای معتبر استفاده کنید، نسخه را Pin کنید و Image را مرتباً اسکن کنید. ساخت Image کوچک‌تر معمولاً سطح حمله و حجم وابستگی‌ها را کاهش می‌دهد.

Secret و Configuration

Password و Token را داخل Image یا Repository قرار ندهید. Secretها باید از مسیر امن و با حداقل دسترسی وارد Container شوند. فایل‌های Compose و CI/CD را نیز قبل از Commit از نظر Secret بررسی کنید.

Network

تمام Containerها نباید به همه سرویس‌ها دسترسی داشته باشند. Networkهای جداگانه بسازید و فقط Portهایی را Publish کنید که واقعاً برای Client لازم‌اند. Database و Redis معمولاً نباید مستقیماً روی اینترنت قابل دسترسی باشند.

Runtime

  • در صورت امکان Container را با User غیر root اجرا کنید.
  • Capabilityهای غیرضروری را حذف کنید.
  • Volumeهای حساس را فقط در صورت نیاز Mount کنید.
  • Log و Resource limit تعریف کنید.

Monitoring

Container health، restart loop، مصرف CPU/RAM، فضای دیسک و خطاهای برنامه باید مانیتور شوند. امنیت بدون Visibility کامل نیست.
