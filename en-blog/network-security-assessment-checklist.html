Network Security Assessment Checklist: Asset Discovery to Incident Response

A security assessment is valuable when it becomes a decision-making process rather than a list of tools. This checklist turns assets, access paths, controls, evidence and gaps into prioritized remediation work.

Author: Mohammad Hossein Asgari SomarinLevel: Intermediate to AdvancedUpdated: September 15, 2026

1. Asset Discovery and Ownership

Start with a reliable inventory of servers, switches, firewalls, access points, cameras, printers, IoT devices, cloud services and remote access points. Record owner, location, IP/VLAN, role, criticality and management path.

2. Attack Surface and Communication Paths

Model real communication paths rather than only listing open ports. Identify Internet exposure, VPN access, remote management, server-to-server traffic and access to sensitive services. Every important path should have a business reason and an appropriate control.

3. Segmentation and Access Control

Review Client, Server, Management, Voice, CCTV and Guest zones. Compare inter-VLAN and inter-zone rules with actual business requirements. Management access should be more restricted than normal user access.

4. Access-Layer Security

Review DHCP Snooping, Dynamic ARP Inspection, Port Security, unused ports and trusted interfaces. Validate each control against the actual switch model and topology before enabling it broadly.

5. Firewall Rule Review

For each rule, review source, destination, service, purpose, owner and logging. Prioritize Any/Any rules, old exceptions, unused objects and rules without ownership. Use logs and hit counts to validate whether a policy is still required.

6. Identity and Privileged Access

Separate daily accounts from administrative accounts. Review privileged groups, service accounts, sensitive GPOs, MFA coverage, management source restrictions and authentication failures. Least privilege should be measurable and reviewed periodically.

7. Logging and Detection

Define which events matter: failed logins, firewall policy changes, privileged group changes, DNS changes, service failures, unusual traffic and backup failures. Logs become useful when important signals have owners and response procedures.

8. Vulnerability and Patch Management

Compare operating systems, network firmware, exposed services and management software with supported versions. Prioritize remediation using exposure, exploitability, asset criticality and compensating controls rather than CVE count alone.

9. Backup and Recovery

Back up firewall and switch configurations, systems, databases and critical files. Then test restoration. An untested backup is an assumption. Record RPO, RTO, storage location and access controls.

10. Incident Response

Maintain short runbooks for detection, containment, evidence preservation, eradication, recovery, validation and lessons learned. Consider the evidence impact before rebooting or cleaning a suspected system.

11. Turn Findings into a Risk Register

Every finding should have evidence, impact, likelihood, priority, owner, remediation and a validation test.

Finding → Evidence → Impact → Likelihood → Priority → Owner → Fix → Validation

12. Definition of Done

An assessment is not complete when controls are merely enabled. It is complete when the important controls are testable: can Guest reach Server VLANs, can a rogue DHCP server be detected, is management restricted to approved sources, and can critical services actually be restored?
