Linux Server Hardening Checklist

Hardening reduces attack surface before an incident happens. Use this checklist as a baseline and define rollback and emergency access before changing a production server.

1. Accounts and privileges

Remove or disable unused accounts, limit administrative access and give services only the permissions they actually need.

2. SSH

Prefer key-based authentication, restrict direct root access where practical and control management access at the network or firewall layer. Changing the SSH port alone is not a security control.

3. Patching

Keep the operating system and exposed services current through a controlled maintenance process. Back up critical data before high-impact updates.

4. Unnecessary services

Use tools such as ss and service management tools to identify listening ports and disable services that are not required.

5. Firewall

Build rules around actual requirements, restrict management paths and document important allow rules. A firewall does not replace patching or least privilege.

6. Logging and monitoring

Authentication, security events, service failures and important configuration changes should be observable and retained long enough to investigate incidents.

7. Backup and recovery

Test restoration, not just backup creation. A backup that has never been restored is an assumption, not a recovery plan.

Authoritative references

Final checklist

  1. Accounts reviewed
  2. SSH controlled and auditable
  3. Patching process defined
  4. Unnecessary ports closed
  5. Firewall policy documented
  6. Logging and monitoring enabled
  7. Restore tested
